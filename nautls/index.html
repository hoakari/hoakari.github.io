IoT環境制御システム「Nautls」

自律型スマート農業を目指し、企画・設計からハードウェア配線・サーバー実装までワンオペで手がける自社開発IoTシステム
2026年7月27日 · 1 分 · Y.Miwa

自律型スマート農業の実現を目指し、企画・設計から実装まで一人で手がけている自社開発IoT環境制御システム「Nautls（ノーチラス）」。（2026年1月〜、継続開発中）

概要#

Raspberry Pi 5とESP32センサーによる環境観測から、FastAPIサーバーへのデータ集約、Streamlitダッシュボードでの可視化・操作までを一気通貫で開発。現在は自室内の温湿度・気圧を10分周期で自律計測するフェーズを完了しており、今後アクアポニックス（魚と植物の共生システム）・キノコ栽培・養蜂など、複数の環境データを自動観測・制御する仕組みへ段階的に拡張していく設計。「人が常時介入しなくても運転を継続できる」ことを前提に、監視・アラート・堅牢性まわりを重点的に作り込んでいる。

工夫した点#

  • Docker Composeで全サーバー機能をコンテナ化し、docker-compose up -dだけで数分で復旧できる運用性を優先。この規模ではKubernetesは制御レイヤーのオーバーヘッドやステートフルDBとの相性の悪さがデメリットとして上回ると判断し不採用
  • PostgreSQL（生物マスタ等、整合性が重要なデータ）とMongoDB（センサーログ等、大量・可変の時系列データ）で役割を分担。SQLModel・BeanieともにPydanticベースのORM/ODMを採用し、FastAPIのスキーマ定義・RDB・NoSQLを共通の型定義で扱えるようにして二重管理を回避
  • 監視・操作パネルはGrafana＋Prometheusではなく、あえてStreamlitを採用。「見る」だけでなく「異常時にしきい値を変更する」「手動でファンを起動する」といった双方向の操作が必須な要件に合わせた技術選定
  • 閾値超過アラート・データ沈黙検知・毎朝の定期サマリーをDiscord Webhookで通知する仕組みを実装し、無人運転中の異常にも気づける体制を構築
  • ESP32側のハードウェアウォッチドッグタイマーや、通信途絶時のローカルバッファリング設計など、フリーズ・瞬断を前提にした堅牢性を重視

主な使用技術#

  • Python
  • FastAPI / SQLModel / Beanie / Pydantic
  • PostgreSQL / MongoDB
  • Streamlit
  • APScheduler
  • Docker / Docker Compose
  • Raspberry Pi 5 / ESP32（MicroPython）
  • Discord Webhook
